## Shared rules and boundaries

- `44px` occurs 12 times in `styles.css` and twice in `winter.css`. It is one repeated size with accessibility meaning. Use one `--target-size: 2.75rem` for control minimum inline and block sizes when applying the approved target fix. Leave unrelated 44 px artwork values independent unless they are actually hit areas.
- `77rem` appears in the common content rail and mast padding calculation. If widening a media band is approved, extract this repeated baseline as `--content-max` and add a wider media rail only where used. Full-width atlas and hero backgrounds already exist. Keep prose measure and position stable at 320–768.
- Existing `--mast`, `--chapter-nav`, and `--chapter-jump` cover sticky chrome. Reuse them and the actual sticky bounds. Do not create separate phone offsets for each control. The `42rem` / `42.01rem` CSS breakpoint and current `matchMedia('(max-width: 42rem)')` JS check define the same compact walk behavior. If JS needs it, use one named helper or the visibility of the actual control. CSS custom properties do not substitute into media conditions.
- Use logical alignment for text, paddings and anchor offsets in changed components. Existing physical layout rules include `.city-tab` and `.action` text alignment, `.chapter-menu > div` right offset, and the itinerary rule and marker `padding-left`, `border-left`, and `left`. These would misalign under RTL. English LTR is the supported direction. Do not broaden this pass into a full RTL implementation or mirror geographical offsets in the map images and projections.
- Shared strings and structures already exist in `chapterLinks`, `photoCredit`, `galleryControls`, and `comparePrices`. Use those as sources. The native picker and full route list intentionally come from the same data. Preserve both renderings if both are needed across breakpoints. A blanket replacement of the chained renderer or a CSS framework brings no measured benefit here.
- The review and tests should stay separate from the published app code. Own `app.js` as one lane, because chapter navigation, route focus, lodging, cost labels and evidence all use its shared factory and delegated events. Another lane can own `styles.css` and the atlas template/script. A stage lane can own `winter.js`, `winter.css`, `winter-stage.tsx` and its bundle. Coordinate selectors up front. Generate the hosted and offline files after integration.
